# 5. Трубочка и один разговор

Голос — по одной реплике: Трубочка → Записать → Стоп и отправить → STT → existing agent → TTS → звук. Это микрофонный разговор в PWA, не PSTN/телефонный номер и не непрерывный duplex call. AudioContext открывается на нажатие. Разрешите микрофон; максимум 30 секунд, WAV mono PCM16 16 kHz до 1 MB. Слишком короткая/невалидная запись не отправляется.

`providers.py` содержит независимые STT/TTS adapters для нейтральных HTTPS JSON gateways. Это наш контракт, НЕ прямая совместимость с OpenAI/другим vendor API. Для своего провайдера реализуйте server gateway/замену adapter: STT POST `{audio: base64Wav, mime: audio/wav, sampleRate: 16000}` → `{text}`; TTS POST `{text}` → `{audio: base64, mime: audio/wav|audio/mpeg|audio/ogg}`. Bearer ключ только server-side. Модель, voice, тариф и дополнительные vendor параметры на стороне вашего gateway. Ошибки без provider bodies/credentials.

Для прямого OpenAI audio есть `OpenAISTT` (multipart file/model/response_format=json) и `OpenAITTS` (speech JSON model/voice/input, mp3). Они обращаются только к фиксированным audio endpoints; chat/model brain здесь не создаётся. Установите STT_PROVIDER/TTS_PROVIDER=openai и STT_MODEL/TTS_MODEL из доступных вашему аккаунту audio моделей, TTS_VOICE по вашему выбору. Выбор модели/голоса и совместимость аккаунта требуют владельца. Форматы сверены по [официальному transcription API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create) и [speech API](https://developers.openai.com/api/reference/typescript/resources/audio/subresources/speech/methods/create); live вызовы UNTESTED. Для нейтрального gateway выберите STT_PROVIDER/TTS_PROVIDER=gateway. По умолчанию оба значения off.

После отдельного разрешения на платные вызовы владелец задаёт ключи и нужные provider параметры (gateway URL или OpenAI audio model), включает ALLOW_STT_API/ALLOW_TTS_API и VOICE_ENABLED. В этой работе live API запрещены и не вызывались. `MOCK_VOICE=1` разрешён только локально: фиксированный синтетический текст, тихий WAV. Это проверка связки, не реальная речь.

Guard: одна активная реплика, без очереди; default 20 запросов/UTC сутки и 2 секунды между новыми; 60 секунд на turn, provider IO не более 30 секунд; STT максимум 2000 символов, TTS максимум 4000 и 2 MB ответа. Отмена и неудачные/неоднозначные попытки учитываются; journal переживает restart. Ограничение считает запросы, не денежную сумму: денежный cap задайте в аккаунте gateway/provider. RAM audio cache: до 6 ответов, 5 минут; GET не пересоздаёт TTS. Если звук истёк/потерян после restart — платной регенерации нет.

Прервать/фон/offline останавливают mic/звук и отправляют cancel best effort. Provider может уже списать деньги; агент может уже сохранить текст. После такого исхода сначала обновите историю. Автоповтора POST нет; новая запись — новый платный запрос. В фоне голос не продолжается.

Приёмка continuity: скажите в Telegram нейтральный проверочный факт → откройте телефон и увидьте те же сообщения → спросите голосом о факте → вернитесь в Telegram и проверьте ответ/продолжение. AgentId/conversationId должны совпасть. Connector не копирует память. Этот тест уже выполнен на fake existing runtime; реальный runtime/provider/телефон требует владельца.
