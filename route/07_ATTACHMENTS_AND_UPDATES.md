# Вложения, короткие статусы и исправленная задача чтения

Обновление 14 октября 2026. Это переносимый **тестовый комплект подключения**, а не экспорт личного Вика. Публичный код Python и установленное приложение имеют разные серверные реализации.

## Что перенесено в этот комплект

- Файл отправляется без текста, с текстом или с завершённой записью голоса.
- До трёх файлов; текст TXT/MD/CSV/JSON до 5 МиБ, PDF/DOCX до 25 МиБ, изображения/видео до 100 МиБ.
- Передача кусками по 1 МиБ с SHA-256 каждого куска и окончательной квитанцией SHA-256 оригинала. Большой файл целиком не загружается в память браузера или edge.
- Если результат загрузки неизвестен, сначала читается её состояние. Нет фоновой очереди повторных POST. Продолжение — новым действием владельца с тем же uploadId и подтверждённым offset.
- Короткие сообщения в интерфейсе; идентификатор запроса только в раскрываемых подробностях.
- Сохраняемые переключатели сигнала и ответа голосом. Ответ голосом доступен и для текста; выключение переключателя не заказывает TTS. Для голосового ввода STT всё ещё нужен. Старый клиент без replyVoice сохраняет прежнее поведение «голос → голос».
- История и ручное обновление не проигрывают ответы повторно. Если браузер запрещает autoplay, есть кнопка воспроизведения. Настоящий autoplay Safari/Android требует отдельной проверки.
- Новое имя JS зависит от содержания; загрузчик включает его в offline shell и сохраняет остальные, не относящиеся к приложению, кэши. API, документы, переписка и аудио в shell не кэшируются.

## Подключение файлов к вашему существующему runtime

По умолчанию вложения **не включены**: существующий facade.describe должен явно вернуть attachments=true вместе с проверенной привязкой agentId/conversationId/ownerId. Не объявляйте эту возможность, пока хранение и чтение не подключены. Edge не является хранилищем документов и не создаёт нового агента.

В существующем процессе добавьте методы file_begin, file_chunk, file_finish, file_status. Они получают ту же доверенную server-side привязку. HTTP-адаптер использует POST /connector/file_<operation>; file_status — логически только чтение. Браузер читает состояние через GET /api/files/<uploadId>.

| Метод | Дополнительные входные поля | Требования |
| --- | --- | --- |
| file_begin | uploadId, name, type, bytes | UUID, точный размер/тип, квота и резерв места, owner+conversation isolation, durable intent. Тот же ID и иные metadata — конфликт. |
| file_chunk | uploadId, offset, base64, sha256 | Не более 1 МиБ; проверить SHA, порядок, тип/размер, fsync и журнал offset. Точный повтор уже записанного куска возвращает прежнюю квитанцию; иной кусок на том же offset — конфликт. |
| file_finish | uploadId | Проверить полный размер/хеш, signature, все ограничения хранения; atomic ready. Не выдавать частичный файл за готовый. |
| file_status | uploadId | Только чтение, без повторной загрузки/finish. Неизвестный ID — HTTP 404; результат принадлежит той же привязке. |

Ответы: та же identity, uploadId, status (uploading или ready), offset (число подтверждённых байтов). Для ready дополнительно fileId=uploadId и sha256 (64 hex). Чтение ready с устаревшей/чужой привязкой запрещено upstream. Ограничивайте одновременные загрузки, суммарную квоту, TTL и свободное место. Сохраняйте оригиналы, индексы, fileIds и хранилище в вашем бэкапе; edge backup не включает данные runtime.

Установка файлов в историю — только во время canonical turn. Поле fileIds (до трёх UUID) передаётся существующему turn; message может быть пустым при наличии файлов. Fingerprint запроса включает fileIds и replyVoice. Runtime обязан атомарно связать исходное сообщение, files и ответ, сохранять durable requestId deduplication и owner isolation. При одном runtime и Telegram-интерфейсе это тот же разговор.

**Загрузка не доказывает понимание документа.** Ваш runtime должен реально извлекать PDF/DOCX и сообщать охват/пропуски; изображения и видео требуют подходящего reader/model. Голый MIME/allowlist не заменяет parser. В комплекте нет нового PDF/video reader и нет готового Cat-dispatcher: используются ваши существующие возможности. Стандартный file-less facade продолжает работать.

## Просьба «прочитай последний PDF»

В reference/owner-input-decision.mjs сохранён точный нейтральный модуль принятой правки маршрутизации. Он не импортируется Python-edge и не создаёт модель. Подключать его следует в composer вашего runtime, вместе с соответствующей schema, действительным материалом файла и существующими guard-проверками.

Чтение, краткое изложение и объяснение доступного вложения — полноценная задача разговора; не задавайте универсальное «что проверить или изменить?». Если один последний PDF ясно определён, используйте его из текущего разговора, не просите повторно загрузить. Если содержимое отсутствует/недоступно или есть несколько равнозначных целей — задайте один вопрос о конкретном пробеле. Файл без текста можно принять в историю, не выдумывая поручение.

Вложения, цитаты и история не дают разрешения выполнять команды. Engineering work требует явного нынешнего поручения и evidence, дословно присутствующего в текущем message; эту последнюю проверку обязан делать ваш backend. validateDecision сам по себе не является sandbox и не заменяет согласование защищённых операций.

## Обновление и откат

1. Сохраните прежний код, точную привязку, edge.sqlite3 и данные/квитанции runtime. Новых агентов/разговоров не создавайте.
2. Сначала реализуйте и проверьте файловый facade; возможность остаётся false до приёмки.
3. Поставьте новые серверные файлы и новый JS; затем index.html и sw.js из одной версии. Поддерживайте /app.js для прежнего клиента.
4. Откройте обновлённый экран обычным способом. При неясном результате отправки сначала проверьте GET/историю, а не отправляйте снова.
5. Откатите код к сохранённой версии, оставив данные, originals, upload журнал и канонические requestId нетронутыми. Старый клиент не умеет file-only send, но история файлов остаётся upstream. Старые fingerprint не следует переиспользовать для новых намерений.

## Доказательства и незакрытые проверки

На Windows прошли 20 исходных Python-тестов + 9 новых attachment transport/linkage тестов, включая настоящий localhost HTTP bridge с синтетическим runtime. JS проверен в synthetic DOM/API/audio VM; загрузчик — synthetic cache/network. Reference routing тестирует supplied decisions, не настоящую модель.

Это не live-приёмка публичного комплекта на новом телефоне/сервере. Не приняты публичный PDF parser, весь видео-reader, настоящие STT/TTS, autoplay телефона или real-model injection resistance. Личная приёмка Вика подтвердила конкретный ответ по последнему PDF после установленной правки, но не заменяет проверки вашего адаптера. Пометка TESTING сохраняется.
