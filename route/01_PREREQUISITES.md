# 1. Что уже должно быть

Работающий Telegram-агент со своим runtime и канонической историей. Доступ владельца к серверному коду/entrypoint либо документированному API. Python 3.10+ для connector, отдельный каталог private data, свободный loopback порт. Для телефона — домен/TLS и reverse proxy; браузер с AudioContext/getUserMedia. Сервер и API-аккаунты не предоставляются этим комплектом.

До подключения выясните реальные `agentId`, `ownerId`, `conversationId` Telegram-разговора. Их задаёт владелец на сервере. Telegram chat ID сам по себе не всегда conversation ID. Браузер не выбирает другого агента или другого человека.

Runtime должен уметь: прочитать историю нужного owner; выполнить реплику через тот же entrypoint, которым пользуется Telegram; сохранить её в той же истории; надёжно дедуплицировать requestId; сериализовать реплики между каналами; поддерживать deadline/cancellation. Если этого нет, сначала нужен небольшой facade внутри runtime, а не второй агент.

У асинхронного бота вызов направляется в его уже работающий event loop. Его память и инструкции остаются там. Нельзя импортировать модуль, который повторно запускает polling, или создавать новый runtime ради HTTP.
